# 公司 Python 程序风格

## 默认遵循

以用户提供的同项目或同类脚本为最高优先级。没有目标母版时，沿用已观察到的公司模式：

- 按执行步骤编号命名程序，例如 `01-公司期间选择.py`、`03-废料报表出具.py`、`04-结果输出.py`。
- 从 Jupyter/Spyder 导出的脚本若带有 `get_ipython().run_line_magic('cd', ...)` 这类 Notebook 自动生成目录切换行，默认视为导出噪声并直接删除；不要为它补兼容包装，除非用户明确要求保留。 对比用户手工改版时，若差异只包含这类目录切换行或 `# In[...]` 编号变化，不要当作业务逻辑变更。
- 使用 `pandas`、`numpy`、`xlwings`、`configparser`、`os` 与 `dateutil.relativedelta` 处理业务数据和 Excel。
- 保留目录变量风格，例如 `root_dir`、`save_dir`、`config_dir`、`sap_dir`、`sap_path`、`business_path`。
- 配置文件中读取 `com_lists`、`fin_period` 及业务 section。
- 读取 Excel 时使用 `app = xw.App(...)`，完成读取或写回后关闭工作簿并终止 Excel 实例。
- 以 `df_0101`、`df_0301`、`result_fl03` 等体现文件或输出编号的变量名组织 DataFrame。

## 公共函数

默认保留并复用已有实现，不因追求抽象而重新设计：

- `get_path(root_dir, text_num)`：按文件前缀寻找输入或输出。
- `find_files(root_dir, prefix_list, file=True)`：按目录层级或文件前缀查找。
- `read(path, sht_num_name=0, row=0, col_list=0)`：通过 xlwings 读取可见 Sheet、表头及所需字段。
- `df_notnull(df, split_list=None, null_list=None)`：清理空值及编号字符。
- 项目已有的表头定位、列号转换、写回和格式复制函数。

注意：`df_notnull()` 的既有实现可能移除前导零。客户代码、凭证号、物料号或其他编码必须保留前导零时，先确认并采用适当处理，不得直接套用。

## 数据处理结构

通常按下列顺序编写：

1. 引入依赖与公共函数。
2. 读取业务配置和生成期间衍生变量。
3. 通过 xlwings 读取源工作簿的指定 Sheet 与列。
4. 做数据类型转换和基础清理。
5. 按业务模块执行筛选、匹配、计算和核对。
6. 按输出列顺序形成 `result_*` 或过程表 DataFrame。
7. 通过 xlwings 更新既有工作簿中的一个或多个 Sheet，或输出新文件。

## 多 Sheet 输出模式

从已有脚本继承以下处理习惯：

- 更新历史报表时，先明确是覆盖整表、删除当期再追加，还是插入当期列并复制公式。
- 按 Sheet 的实际标题行匹配列名后再写入，避免依赖固定列序。
- 需要保留格式时，复制上一期/上一行格式或公式后再写数据。
- 新增月度明细 Sheet 时，先判断当期 Sheet 是否存在，并按业务要求替换。
- 金额列、百分比、日期、长数字及编码字段分别设置格式和文本保护策略。

## 默认禁止行为

- 不将用户已有的多步骤脚本自动合并成单文件。
- 不默认重构公共读取函数、配置结构或输出模板。
- 不凭空补写会计口径、匹配优先级或未匹配处理方式。
- 不用读取样例所得的“看起来合理”结果代替业务核对确认。
