# 发票 PDF 识别与汇总输出脚本参考

## 适用场景

当财务需求包含进项发票 PDF 识别、抵扣勾选清单匹配、上传版生成、发票清单总表、固定资产汇总或 PDF 汇总打印时，优先按多步骤脚本拆分，并参考本文件。

典型拆分：

- `01-公司期间选择.py`：读取或初始化 `business_config.ini`，选择公司和期间，创建当期目录。
- `02-汇总勾选数据匹配.py`：读取抵扣勾选清单，识别 PDF，按发票号匹配，输出抵扣清单和上传版。
- `03-汇总清单及打印.py`：汇总上传版，合并历史总表和固定资产表，整理 PDF 打印目录，生成汇总工作簿。

不要把 PDF 识别、上传版生成、历史汇总和 PDF 打印强行合并到一份脚本。它们通常有独立输入输出、可单独重跑，也有不同的人工检查点。

## 目录与配置

保留公司现有目录命名：

- `1.原始数据`
- `2.运行结果`
- `3.上传版`
- `4.汇总打印`

当公司代码为 `1100` 或名称包含 `分公司` 时，通常使用公司级目录：

```python
def is_company_scoped(company_code):
    return company_code == '1100' or '分公司' in str(company_code)

def get_company_base_dir(company_code):
    if is_company_scoped(company_code):
        return os.path.join(os.getcwd(), company_code)
    return os.getcwd()
```

发票 PDF 原始目录常见结构：

```text
<base_dir>/1.原始数据/进项发票PDF/<fin_period>/
  应收/
  应付/
  总账/
  资产/
```

`01-公司期间选择.py` 可用 Tkinter 单窗口选择公司代码和期间；期间必须校验为 `YYYYMM`。确认后更新 `business_config.ini` 中的 `com_lists`、`fin_period`，并创建原始 PDF、运行结果、上传版和汇总打印目录。

## PDF 文本识别规则

发票 PDF 不要只依赖 `page.get_text()` 的默认顺序。部分电子发票会把标签模板和动态值放在不同内容流中，默认文本顺序可能出现“所有标签在前、所有值在后”的错位。优先使用 PyMuPDF 的坐标词块重排：

1. 用 `page.get_text("words")` 取得 `(x0, y0, x1, y1, word, ...)`。
2. 先按 `y0` 分行，允许小的 `y_tolerance`。
3. 每行内按 `x0` 排序。
4. 将重排后的文本用于正则提取。
5. 如果坐标提取为空，再回退到 `page.get_text()`。

大量发票批量识别时，发票号码、买卖方、金额、税额等关键信息通常在第一页。默认只读第一页以减少卡顿，除非业务样例证明关键字段会出现在后续页。

## 发票字段提取原则

识别号提取必须限制在合理区域内，不要全文盲抓 15-20 位字母数字串。

推荐顺序：

1. 按 `购买方` 到 `销售方` 之间截取购买方区域。
2. 按 `销售方` 到 `备注/开票人/收款人/复核人` 之间截取销售方区域。
3. 在对应区域内匹配 `纳税人识别号`、`统一社会信用代码`、`纳税人识别号/统一社会信用代码`。
4. 若区域匹配失败，再处理左右双栏版式：同行或紧邻处出现两个识别号时，按先买方后卖方解释。
5. 仍失败时宁可留空进入待查验，不要全页兜底误抓。

必须过滤明显不是税号的值：

- 20 位纯数字数电发票号码。
- 12 位发票代码。
- 8 位发票号码。

发票号码识别建议：

- 数电发票优先匹配 `发票号码` 标签后的 20 位号码。
- 若标签错位，可从重排文本行中寻找 20 位数字。
- 纸质发票用 `发票代码` 12 位 + `发票号码` 8 位作为组合键。

金额识别建议：

- 优先识别含 `合计` 的明细合计行，取不含税金额和税额。
- 跳过 `价税合计`，避免把含税合计误作不含税金额。
- 文本压成一整段时，再用紧邻 `合计` 的两个金额作为兜底。

红字发票通过 `红字发票` 等关键词识别，状态中必须保留红字提示，默认进入待查验或单独标记。

## 买卖方兜底校正

如果已知自家公司税号，并且 PDF 同时识别到买卖双方两个税号，可以结合文件夹方向进行强校正：

- `应付`：自己通常是购买方，对方是销售方。
- `应收`：自己通常是销售方，对方是购买方。

该规则只应在业务确认的文件夹中启用，例如 `应付`、`应收`。两个税号都不是自家公司，或两个都是自家公司时，不能用这条规则强行判断。

匹配成功时，不要用 PDF 识别出的税号覆盖勾选清单已有税号。只在勾选清单字段为空时补充 PDF 识别结果，避免 PDF 误识别污染上传版。

## PDF 与勾选清单匹配

先从勾选清单建立两个查找字典：

- 数电发票：`数电发票号码 -> 行索引`
- 纸质发票：`(发票代码, 发票号码) -> 行索引`

遍历 PDF 时保留：

- 首次匹配成功清单。
- 重复匹配清单。
- 未匹配 PDF 清单。
- 每个一级或相对文件夹的 PDF 数、匹配数、未匹配数、重复数。

重复和未匹配 PDF 也要进入结果表，状态写成可人工追踪的形式，例如：

- `待查验-重复-应付`
- `待查验-红字发票-应收`
- `待查验-普通发票-资产`

处理结束后建议复制 PDF 到：

- `PDF匹配OK/<YYYYMMDD>`
- `PDF匹配NO/<YYYYMMDD>`

并输出总数、首次匹配数、重复数、未匹配数、最终结果行数。最终结果行数应能和 PDF 总数对齐，除非业务明确按勾选清单行数输出。

## 上传版生成

上传版只取状态不为空且不包含 `待查验` 的记录。默认设置 `是否勾选* = 是`。

上传版应优先复制业务模板，再按模板表头定位写入列，而不是按固定列序硬写。若上传数据列在模板中不存在，打印跳过列清单；若没有任何列匹配，应直接报错。

写入前注意：

- `数电发票号码`、`发票代码`、`发票号码`、税号等长数字或编码列必须作为文本。
- 日期和金额字段分别转换，转换失败保留为空或进入异常检查。
- 不要把 `待查验`、重复、红字待确认或未匹配数据放入上传版。

## 汇总清单与 PDF 打印

汇总打印脚本通常读取当月上传版和抵扣清单，合并出当月明细。

推荐规则：

- `发票号码` 为空时，可用 `数电发票号码` 填充，方便汇总展示。
- 当月明细新增 `所属期`。
- `PDF路径` 在汇总表中重命名为 `PDF链接`。
- `PDF链接` 写入 Excel 时使用 `HYPERLINK` 公式，显示文本可统一为 `PDF链接`。
- 固定资产 Sheet 合并上期历史和本期资产类数据。
- 总表合并上期总表和本期明细后，按 `发票代码 + 发票号码` 去重，保留最后记录。
- 重新生成 `序号`，不要沿用来源文件序号。

PDF 打印目录可按规则整理：

- 资产类进入 `4.汇总打印/<fin_period>/资产`。
- 非资产的数电发票或增值税专用发票按每 100 张一册，例如 `第1册(纸票+电子票1-100)`、`第2册(101-200)`。
- 复制后的文件名建议加四位序号前缀，如 `0001_原文件名.pdf`，保证打印顺序稳定。

## Excel 输出格式

生成汇总工作簿时，如有上期工作簿，应优先复制上期作为底稿，保留原 Sheet 顺序和样式，再更新本期 Sheet。

输出格式建议：

- 第 1 行合并标题，例如 `发票清单`。
- 第 2 行写纳税人名称、所属月份、单位。
- 第 3 行为表头，数据从第 4 行开始。
- 冻结第 3 行。
- 表头加筛选、颜色、加粗。
- 金额和税额使用千分位两位小数格式。
- 日期使用 `yyyy/mm/dd` 或业务要求格式。
- 文本列写入前先设置整列文本格式，必要时值前加单引号。
- `PDF链接` 列用超链接公式，不再额外设置文本格式。

## 性能与稳定性

Excel 读取包含超链接的表时，不要逐单元格调用 COM 读取超链接。先快速扫描前几行是否存在 `PDF链接` 字样；只有存在时才处理超链接。

优先遍历 `used_range.api.Hyperlinks` 集合，按超链接所在单元格换算相对行列位置写回内存数据。这通常比 Python 逐单元格访问快很多。COM 超链接集合失败时，再回退逐单元格读取。对 `HYPERLINK("path","PDF链接")` 公式，另行解析公式文本作为兜底。

批量处理 PDF 或复制文件时，每 100 或 200 个文件打印一次进度，避免业务人员误以为程序卡死。

## 验证清单

交付前至少核对：

- PDF 总数、结果行数、匹配 OK、匹配 NO、重复数是否逻辑一致。
- 数电发票、纸质发票都能匹配。
- 双栏电子发票买卖方识别正确。
- `应付/应收` 文件夹方向校正没有误套到其他文件夹。
- 红字发票状态保留待查验提示。
- 勾选清单已有税号没有被 PDF 识别值覆盖。
- 上传版不含 `待查验` 数据。
- 长数字列在 Excel 中没有变成科学计数法。
- 汇总表中的 PDF 链接可点击。
- 固定资产和总表合并历史数据后已重新编号并去重。
