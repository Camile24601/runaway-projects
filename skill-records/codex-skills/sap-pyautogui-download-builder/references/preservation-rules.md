# 保真修改规则

## 目标

在公司已有 SAP 自动化程序基础上新增或修改下载任务，避免 AI 在无授权情况下改变已验证的公共操作行为。

## 优先级

1. 用户指定的目标 `.py` 文件是修改时的直接母版。
2. 没有目标文件时，使用 `assets/company-sap-download-mother-reference.py` 作为新脚本的公共结构参考。
3. 本文仅用于约束变更范围，不覆盖目标脚本已经存在的项目特定约定。

## 默认不改的公共段

除非用户明确提出框架改造或修复公共函数，保留以下代码的原函数体和调用习惯：

| 公共段 | 保留原因 |
| --- | --- |
| `get_path()` | 公司现有文件前缀获取方式 |
| `read()` | `xlwings`、sheet 选择和列筛选的标准读取方式 |
| `df_notnull()` | 现有数据清洗方式，但使用前需核对前导零规则 |
| `find_hwnd_*()` | SAP 窗口检测方式 |
| `click_multi_logon()` | 多人登录处理流程 |
| `mul_choice()` | SAP 多项选择粘贴方式 |
| `load_complete()` | 通过菜单变化识别加载完成的方式 |
| `save_excel()` | ALV Excel 导出流程 |
| 登录与退出段 | SAP 环境操作流程 |
| 期间选择与数据备份段 | 默认保留四输入框、密码脱敏、`Enter` 提交、配置初始化及上期目录备份方式 |

## 允许变更的业务段

通常只改以下位置：

| 位置 | 变更内容 |
| --- | --- |
| `ticode_number_map` | 输出编号列表，例如 `'ZMM020': ['1-1']` |
| `ticode_dict` | 输出说明列表，例如 `'ZMM020': ['采购订单明细']` |
| `load_<TCODE>()` | 用户明确描述的键盘操作和变量输入 |
| 上游数据准备段 | 读取某个前缀文件中的指定列，准备给 `mul_choice()` |
| 特殊执行/保存段 | 只有用户或已验证母版明确要求时增加；F.19 布局处理优先放在 `load_F19()` |

## 修改已有脚本时的规则

- 在原文件上最小修改，不将其转换为新框架。
- 从 Jupyter/Spyder 导出的 `get_ipython().run_line_magic('cd', ...)` 和 `# In[...]` 编号变化视为导出噪声；修改或对比 SAP 下载脚本时默认删除/忽略，不作为业务段变更。
- 不用新的 `read_excel_column()`、`DownloadTask`、`RuntimeContext` 或 registry 取代原代码，除非用户明确要求重构。
- 对源脚本已存在但与本次需求无关的异常写法，只提示风险，不趁机改动。
- 若本次新增逻辑需要修复目标脚本中紧邻的明显错误，先向用户说明该修复与需求的关系。

## 新建脚本时的规则

- 从公司母版复制公共段，不从抽象的全新框架生成。
- 将母版中仅属于示例项目的 TCode、业务读取段和特殊分支替换为当前任务。
- 保留配置文件读取方式；账号密码不得写入脚本。
- 完整项目包含 SAP 下载时，默认同时生成或保留 `01-公司期间选择.py` 和 `02-SAP数据下载*.py`；自动创建缺失的登录配置和业务配置 section，保留上期目录备份步骤，并向用户确认重复备份时的覆盖处理。
- 母版参考文件含脱敏占位值，生成给真实项目的脚本时，仅从用户指定目标环境或已有批准脚本中继承配置。

## 生成后的核对

- 每个导出 Excel 都应在 `ticode_number_map` 与 `ticode_dict` 中有一致项。
- 每项下载均存在对应 `load_...()` 函数。
- 多输出 TCode 的函数名使用 `_1`、`_2` 等序号。
- 上游数据在调用 `mul_choice(df_01['列名'])` 前已读取并清洗。
- 明确编号是否允许删除前导零。
- 特殊保存函数只有在脚本中真实定义时才能调用。
- SAP 导出后必须避免 Excel 自动打开或弹窗干扰后续点击：优先沿用母版中已验证的 `save_excel()`，在点击保存前记录 `excel.exe` 进程集合，保存后只终止本次新增的 Excel 进程，并恢复 SAP 前台窗口。
- 若需要处理导出后自动打开的 Excel，优先使用版本3的“前后 Excel PID 差集”策略；不要粗暴关闭所有 Excel 实例，除非目标脚本原本就是独占 Excel 环境且用户确认。
- 布局切换应优先使用 `LAYOUT_BY_ITEM` 和 `LAYOUT_BY_TCODE` 配置：先按下载条目如 `ZMM020_1` 精确匹配，再按 TCode 兜底；F.19/FAGLL03H 等已有特殊布局处理的 TCode 默认不走通用 `choose_layout()`。
- 若用户提到“布局”“视图”“变式”“variant”或同一 TCode 多个输出口径，确认稿必须列出每个输出文件对应的布局名称，以及布局查找失败时是否报错停止。
- 公司/系统判断应先归类为 KUS、AWS、GROUP：8400/8500 归 AWS，普通公司归 KUS，`kus`/`集团` 归集团；AWS 与普通 KUS 公司默认不得混跑，集团场景可按用户确认拆成 KUS 与 AWS 两套登录/下载流程。
- 若项目需要多系统登录，不要把真实系统 IP、账号或密码写入 skill/GitHub；只保留 `system_name`、`login_section`、`kus/aws` 账号字段的抽象模式，真实值来自用户配置文件。
- ZMM003/资产主数据等超大范围下载可按物料编码区间分批执行，例如数字段与字母段分批；文件名应带系统来源和批次标识，便于后续数据库导入识别。
- 多批次下载后返回选择界面时，优先使用已验证的返回函数或 `load_complete(max_duration=..., pre_name=...)` 判断界面变化；不要仅靠固定 sleep 判断已经回到选择屏。
- 执行 `python -m py_compile` 检查语法。
- 如生成期间选择脚本，核对项目路径、`login_section`、已由用户确认的 `business_section`、默认公司代码提取、密码脱敏显示、备份目录名称、备份期间计算和同期间覆盖规则。
- 实际 SAP 运行前，由用户确认屏幕位置、Tab/Down 顺序、弹窗和导出路径。
- 生成 `02` 脚本时，若母版保留了“所有文件已存在则全量替换重新下载”的逻辑，不要擅自改成跳过；除非用户明确要求“仅补下载缺失文件”。
