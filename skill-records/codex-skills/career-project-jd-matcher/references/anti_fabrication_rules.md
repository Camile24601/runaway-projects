# Anti-Fabrication Rules

## Non-Negotiable Rule

Every resume claim must be supported by the master resume, user-provided facts, or concrete project artifacts. If evidence is missing, write a question, a gap, or a confirmation-needed note instead of adding the claim.

## Claim Categories

### Allowed Without Extra Confirmation

- Tools and languages present in code imports, package files, scripts, filenames, or user-provided text.
- Deliverables visible in the project, such as `.py` scripts, `.xlsx` templates, dashboards, reports, Markdown docs, or generated assets.
- Workflow facts visible in code or docs, such as reading Excel files, cleaning data, matching fields, exporting reports, or automating SAP GUI steps.
- Existing resume facts, rewritten for clarity or JD alignment.

### Needs User Confirmation

- Time saved, cost saved, percentage improvements, volume processed, number of users, number of teams, business adoption, production deployment, recurring usage, and stakeholder impact.
- Ownership level such as `led`, `owned`, `managed`, `architected`, or `drove`.
- Confidential company/client names, business-sensitive process names, or internal system names.
- Whether Codex-assisted work can be described as independent delivery in the target resume context.

### Prohibited Unless Explicitly Supported

- New employers, titles, dates, degrees, certifications, awards, publications, patents, or internships.
- Seniority claims not present in the resume or evidence.
- Tools, platforms, or domains that only appear in the JD, not in the user's evidence.
- Quantified outcomes invented to sound stronger.
- Claims of production deployment, team leadership, or cross-functional ownership without evidence.

## Resume Drafting Pattern

For every drafted bullet, keep an internal evidence map:

```text
Draft claim:
Evidence source:
Evidence strength: strong / medium / weak
Unsupported parts:
Action:
```

Only include `strong` and `medium` claims in the resume draft. Put `weak` claims into a confirmation list.

## Safe Rewrite Moves

- Reorder bullets to place the most JD-relevant facts first.
- Replace generic verbs with more precise verbs supported by the evidence.
- Expand abbreviations when supported.
- Group related tools into a concise stack.
- Convert project artifacts into business-facing descriptions.
- Remove irrelevant details for a specific JD.

## Unsafe Rewrite Moves

- Adding a JD keyword just because it would improve matching.
- Turning a learning project into paid professional experience without user confirmation.
- Converting tool exposure into expert-level mastery.
- Adding metrics because the resume sounds better with numbers.
- Hiding important uncertainty.

## Output Warnings

If tailored content uses Codex/local project evidence that is absent from the master resume, add:

```text
New evidence-backed addition: this comes from local project artifacts, not the original master resume. Please confirm it is appropriate to include.
```
